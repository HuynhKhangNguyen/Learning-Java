# R02c durable delivery foundation — working contract

[Task/DoD](../../../docs/platform/delivery/tasks/BL-R02c.md) · [MS03](../../../docs/architecture/data-protocols.md) · [Common wire](../common/README.md)

Authenticated direct mTLS HTTP, no browser/edge routing, Cookie/Origin/forwarded principal or raw answer/private expected. Schema version1, UUID canonical lowercase, bigint sequence as decimal string, UTC millisecond timestamps, strict UTF8/JSON duplicate/unknown keys rejected. Envelope max8192bytes; stored payload max4096bytes, canonical RFC4648 base64 in wire field `payloadBytes`. SHA256 is over decoded exact bytes, not a reserialized JSON tree. Stored envelope bytes and SHA256 are immutable across retries.

Envelope fields: schemaVersion, messageId, operationId, correlationId, producer, consumer, environment=`lab` (owned-lab profile only), authRealmId, producerGeneration, participantGeneration, streamKey, deliverySequence, type, phase, payloadBytes, payloadDigest, createdAt. Stream key1–128 ASCII letters/digits/colon/underscore/hyphen. Type/phase1–64 uppercase ASCII identifiers; consumer adapter allowlist decides supported type/phase/payload, caller certificate must equal producer and consumer must equal receiver. Receiver/current config validates realm and both generations before local effect. Timestamp is immutable provenance, never ordering or expiry authority.

`LAB_APPLY`/`APPLY` is a fixture registration with local SQL probe payload, not an implementation of EVT01–05/publication/lifecycle. Future owning task adds its typed adapter; unknown type/schema is poison, not a success or generic domain apply. Java ports enforce producer callback + sequence/outbox atomic and receiver guard + inbox/effect/receipt/cursor atomic on the supplied own Connection. No network inside transaction, callback self-commit/close or other-connection effect.

ACK after local commit: schemaVersion, receiver, producer, messageId, operationId, type, phase, streamKey, deliverySequence, authRealmId, producerGeneration, participantGeneration, envelopeDigest, payloadDigest, disposition=`APPLIED|REJECTED_NO_EFFECT`, receiptHead, durable=true. Sender validates every binding and expected generation, not just HTTP200. Stored ACK is immutable and duplicate exact message returns the same bytes after current adapter guard. Delivery result is not business canonical/global COMPLETED.

Strict stream starts1. Same ID/sequence different envelope conflicts; future sequence returns STREAM_GAP with no effect/advance, old sequence without exact retained receipt/proven covered prefix returns RESYNC_REQUIRED. Poison quarantine stores bounded metadata/digests/reason only; no raw payload logs. Maintenance recovery requires exact offending digest, expected cursor/verified covered prefix, current realm/participant generation, new recovery generation, immutable producer abort provenance and audited reason. No browser override, edited payload under old ID, cursor reset, guessed commit state or auto-skip. Business publication ABORT/whole-system restore remain R06/R32 owners; missing provenance stays pending/quarantine.

Dispatcher lease uses own DB clock/token and sends outside transaction. Stale token/expired lease cannot record ACK or failure for a later claimant. Up to8 attempts, exponential1s→cap30s plus bounded jitter; transient timeout/network/503 retained pending, exhaustion PAUSED/alert. Permanent schema/domain/caller/generation/digest errors pause/quarantine, not blind retries. No automatic drop or timeout-success. Config/performance/load/retention and production secret lifecycle have later owners.

Auth INT02 uses independent durable per-operation/consumer rows and leases, no strict event cursor or publication/lifecycle FK. Exact own stored fence bytes and the existing [receiver contract](../admission/README.md); only Identity is sender, ACK binds participant/digest/realm/generation/scope/floor/session/context/durable. This lane does not clear canonical pending, issue admissions/reauth proofs or claim full revoke completion before R04d.

## Owned-lab runtime/qualification boundary

Working implementation has an explicit single `delivery` profile, not a pilot/default profile. It uses the existing owned trust config plus `backendlab.delivery.config` in the same immediate `.tools/trust-lab/run-*` directory. Exact keys: schemaVersion=1, enabled=true, adapter=LAB_APPLY, realm, generation, dbRunId, identityGeneration, contentGeneration, learningGeneration. UUIDs must be canonical lowercase; duplicate/unknown keys, mismatched own/peer generation or unready/maintenance DB fail before listener. No runtime migration/provision or dynamic arbitrary DSN.

Private PUT `/internal/v1/delivery/messages/{messageId}` is registered only in this owned fixture profile after mTLS/private-listener/header/route validation. `LAB_APPLY/APPLY` accepts only object `{delta:1}` and commits a test-only SQL transaction_probe effect; no production EVT01–05 or learner state adapter. Content/Learning keep their existing Identity-only INT02 fence receiver in this profile, with own auth realm/readiness checks. No public/edge delivery route, credential/cookie/auth principal forwarding or generic application effect.

Each JAR includes an explicit FX04 `DeliveryLabCli` driver (`PropertiesLauncher`, named own main class) used by the managed test harness: enqueue fixture input on own DB role, then bounded dispatch outside transaction. Identity additionally has auth-enqueue/auth-dispatch fixture operations. Driver writes only bounded delivery result/error tokens, never input/properties/exceptions; it does not create or complete canonical auth operations. A named peer certificate/receiver identity is checked even for the validated loopback peer port. These are lab verification entry points, not a new production maintenance protocol/deployment recommendation.

Sender additionally verifies `receiptHead = SHA256(previous delivered/recovered head + LF + exact envelopeDigest + LF + APPLIED)` under its own transaction; first prefix uses64zeroes. Missing/stale/unproved previous receipt or a valid-format but incorrect head is not delivered. Automatic dispatch cannot jump over PENDING/PAUSED/ABORT_PENDING strict predecessors. Exact REJECTED_NO_EFFECT is not accepted by normal delivery completion; audited maintenance recovery needs its own provenance-bound path. Current task checkpoints distinguish preliminary store/relay evidence from full DATA10–15/abort/prefix/generation recovery qualification.

## Maintenance foundation ports — not production restore/publication authority

Retained covered-prefix proof checks every contiguous inbox receipt fromZERO, exact ACK metadata/disposition/digest/head and current cursor. Rejected entries also require the consumed authorization and immutable producer abort provenance. Missing/corrupt/compacted proof stays denied; this foundation scans at most10000 receipts (SQL capped10001 to detect overflow) and fails closed beyond the lab bound, not a production capacity/retention claim.

Maintenance ports require this service's own migrator role and current ready environment with maintenance=true; normal runtime app cannot authorize or perform recovery. An operator registers immutable recovery ID/new coordinator recovery-generation, exact message/operation/service/realm/both DB generations/offending digest/covered prefix/bounded audit reason. This new recovery-generation versions the coordinator authorization; it does not assert that DB generations/auth realm were rotated or the whole system was restored. There is no public/private HTTP recovery endpoint or caller-supplied browser override.

Producer ABORT requires a trusted owning SQL adapter to lock/reread canonical state and make pre-commit ABORT terminal in the same transaction as immutable proof and ABORT_PENDING. No proof from a timeout or merely finding an outbox. A committed candidate must be denied, and its owner must prohibit later canonical commit after terminal ABORT. Status retrieval is a trusted authenticated named-producer port outside receiver transactions; it returns the exact stored proof bytes. R02c's test-only cross-artifact own-role driver uses a guarded SQL operation probe, not a production publication/status provider. That driver is in test classes and excluded from service JARs.

Receiver locked-rereads maintenance authorization, current domain guard, exact quarantine metadata and verified prefix; REJECTED_NO_EFFECT receipt/inbox/audit/cursor commit atomically without invoking the payload effect. Distinct producer maintenance acceptance binds the same registered authorization, own immutable ABORT proof and recovered ACK; normal dispatch still cannot accept REJECTED. Audit/proof/authorization cannot be edited or deleted through supported ports. Retry does not repeat either effect or ABORT. The ports do not automatically resume maintenance, skip future gaps, rewrite old payloads, rotate DB environments or complete auth operations.
